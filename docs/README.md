## Read this first

| If you are… | Read |
|---|---|
| A product owner or stakeholder | `srs/SRS-00-introduction.md`, then the SRS part of the mode you care about, then `07-KNOWN-LIMITATIONS.md` |
| A developer joining the project | `design/SDD.md` → `design/DATABASE.md` → `design/EDGE-FUNCTIONS.md` → `06-OPERATIONS.md` |
| A tester | `04-TEST-PLAN.md` → `tests/TEST-DATA.md` → the test cases of your mode (`tests/TC-*.md`) → `test-automation/README.md` |

## Keeping the documents true

1. Behaviour changes → update the requirement in `srs/`, then the test cases that name it in their **Requirement** line.
2. New requirement → give it the next free number in its area (`FR-WRK-0NN`), add at least one test case.
3. Run `python3 docs/build-docs.py`: it rebuilds the index, the traceability matrix (and lists requirements with no test case), the execution-log template and `SRS-complete.md`.
4. Database or function change → update `design/DATABASE.md` / `design/EDGE-FUNCTIONS.md` and `06-OPERATIONS.md` if a deploy step changes.
5. Keep `CHANGELOG.md` (the source of truth for history) and the version number in `shared/supabase-config.js` in step.

## Conventions in short

`FR-<AREA>-<NNN>` functional requirement · `NFR-<AREA>-<NNN>` non-functional · `TC-<AREA>-<NNN>` test case · priority P1 (release blocker) to P3 · "TBC" = could not be confirmed from the code · **Device only** = needs a real phone or second device. Full rules: [CONVENTIONS.md](CONVENTIONS.md).
